\subsection{Materials and Data: Cross-City Mobility Traces with Urban Context}
Our goal is to learn a behavioral reference frame from functional cities and apply it to Detroit. This requires (i) large-scale mobility traces, (ii) a shared spatial representation to align multi-source context, and (iii) a data contract that makes cross-city processing auditable.

\paragraph{Study region and city grid.}
We define a Detroit core bounding box in WGS84 coordinates and discretize it into a $1024\times 1024$ grid (approximately 25 meters per cell). The grid is a shared coordinate system for: (i) representing trajectories, (ii) rasterizing map-derived priors, (iii) building POI semantic rasters, and (iv) indexing overhead imagery tiles. This unified representation makes geographic validity measurable and avoids silent misalignment between data sources.

\paragraph{Trajectories: WorldTrace.}
WorldTrace provides large-scale GPS trajectories with per-point timestamps and both raw and map-matched coordinates. We apply a simple, auditable map-matching quality rule: if the matched coordinate is within a fixed distance threshold, we use it; otherwise we fall back to the raw coordinate. Since WorldTrace is standardized to 1Hz, motion statistics have explicit time semantics and do not require heuristic resampling.

\paragraph{Segment extraction and prediction windows.}
WorldTrace trajectories are stored as many per-trajectory files. We extract Detroit segments by filtering points within the Detroit bounding box and splitting the sequence when adjacent timestamps have a gap larger than a fixed threshold (e.g., $\Delta t>5$s). For each trajectory file, we keep the longest contiguous in-bbox segment and discard short segments (e.g., fewer than 120 points). From each retained segment we sample fixed-length prediction windows, using an observation length $H=8$ and prediction horizon $F=12$ at 1Hz. Global context includes time-of-day and day-of-week features and the window-level origin and destination.

\paragraph{Detroit as study context.}
Detroit serves as the target city where we seek rupture signatures. It exhibits pronounced spatial heterogeneity: revitalized corridors coexist with large areas of disinvestment. Our analysis treats Detroit as the target domain, and one or more functional cities as reference domains (chosen to be comparable in scale and data availability). The reference-city selection and functional$\to$functional transfer audit are part of the evaluation design.

\paragraph{Soft geographic prior: OpenStreetMap road proximity.}
We download OpenStreetMap (OSM) road geometry for the Detroit region and rasterize a driving-road mask onto the Detroit grid. Instead of using this mask as a hard feasibility constraint, we compute a continuous road-proximity field (\texttt{road\_prob}) from the distance-to-road map. Intuitively, \texttt{road\_prob} is high on or near roads and decays smoothly as one moves away from roads. This signal is used both as an input feature and as a differentiable regularizer in training, so it can guide learning while remaining robust to map gaps or minor misalignment.

\paragraph{Functional semantics: SafeGraph POI.}
SafeGraph Places provides geolocated POI with coarse and fine categories and basic temporal metadata. We select a fixed monthly vintage to avoid temporal leakage and rasterize POI densities (and optionally category-conditioned densities) onto the Detroit grid. These rasters represent functional context (e.g., retail, education, healthcare, transportation), which can explain detours that are not purely geometric.

\paragraph{Built-environment appearance: ArcGIS Wayback imagery.}
ArcGIS Wayback provides multi-temporal overhead imagery tiles. We download a small set of release snapshots for the Detroit region and store zoom-level tiles on disk. For modeling, imagery is accessed by deterministic tile indexing and aligned to the same Detroit grid. Wayback imagery complements POI coverage by capturing built-environment structure such as waterways, parks, and large facilities.

\paragraph{Data contract and reproducibility.}
All preprocessing steps (trajectory segmentation, grid mapping, and rasterization) are parameterized and recorded. This enables reproducible experiments and supports audits that separate model failure from data alignment issues.
