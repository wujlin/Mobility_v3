\subsection{Implementation details (graph cascade)}
\paragraph{Road graphs and coordinate system.}
We discretize each city into a shared $1024\times 1024$ grid (per-city bounding box) and build a directed road graph from OpenStreetMap.
Nodes store grid coordinates and edges store length and tier type (major/minor/service).

\paragraph{Candidate coverage diagnostic.}
For the $K$-shortest baseline we use a Yen-style enumeration with $K=20$ candidates per OD and evaluate best-of-$K$ edge Jaccard to the GT graph path (Sec.~\ref{sec:problem-setup}).

\paragraph{Waypoint AR.}
The waypoint AR model uses a $32\times 32$ waypoint binning ($1024$ classes) and predicts a fixed number of waypoints (4 decoding steps in our current prototype).
We condition on cyclical time features (hour-of-day and day-of-week) and road-tier features.

\paragraph{A* execution.}
We run A* between consecutive waypoints using edge length costs.
If any segment is unreachable, the sample is marked as a failure and does not contribute to corridor-match metrics, which are reported alongside the success rate.

\paragraph{Note on legacy window-level experiments.}
Earlier experiments in this repository used fixed-length sliding windows of trajectories.
We do \emph{not} use window-level results as evidence for trip-level route generation, since window sampling can remove corridor-level decisions; segment-level audits are required (see `docs/PI_BRIEF_ROUTEGEN_ICML2026.md`).
